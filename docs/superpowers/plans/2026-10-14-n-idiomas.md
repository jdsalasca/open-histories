# Plan de implementación — N idiomas (Fase 2)

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Sumar un idioma a open-histories = **config + archivos** (entrada en el registro + contenido + catálogo), sin cambios de lógica; `es/zh/en` idénticos; publicado a GitHub (`main`) y prod al cerrar cada ronda.

**Architecture:** Nuevo registro puro `assets/langs.js` (`OH.lingo`) con los idiomas y sus particularidades (nombre endónimo, voz TTS, base, anotación pinyin). `settings/text/panel/reader/offline/i18n/validate/pinyin.py` dejan de tener `es/zh/en` fijos y lo consumen. Prueba: agregar una entrada `META.fr` en tests basta para que el motor acepte el idioma; receta documentada.

**Tech Stack:** JS vanilla (sin build), `node --test` (Node 24), Python (pypinyin) para generar idiomas, sitio estático + `deploy.sh`, capturas con Chrome headless.

**Spec:** `docs/superpowers/specs/2026-10-14-n-idiomas-design.md`

## Global Constraints

- Comandos de calidad antes de cada commit de ronda: `node --test tests/*.test.js` · `node tools/validate.js` · `uv run --with pypinyin python -m unittest tests.test_pinyin`.
- Windows: `PYTHONIOENCODING=utf-8` si se imprime chino. Sin dependencias nuevas. Sin secretos.
- No tocar: contenido existente (`stories/*.js` generados no se editan a mano), servidor (§8), Fases 3–4.
- Commits pequeños en `main`; **push + deploy al cerrar cada ronda** (pedido explícito: "ve publicando en producción… en github … main").
- Deploy: `bash deploy.sh atopnuc@192.168.1.100:/home/atopnuc/sitios/open-histories` (Git-Bash) · rollback `--rollback` · verificación post-deploy (hash, 3 idiomas, hotel 200).
- Capturas: mismo procedimiento del plan `docs/superpowers/plans/2026-10-14-modo-chino.md` (Anexo A): perfil de Chrome limpio por tanda, móvil `--window-size=500`, borrar `_shot.html`/`_shot2.html` antes de cada push.
- Subagentes: nunca Opus ni Fable (AGENTS.md §2.7).

## Review Focus

1. Regresión de `es/zh/en` (lo más probable de romper): lectura y estudio en los 3 idiomas — capturas + tests existentes.
2. `OH.lingo` (registro) vs `OH.langs` (datos de cuentos de `OH.lang(...)`): no pisarse — aserción en tests.
3. Fallback de carga: si `langs.js` no está, settings/text deben seguir con el default estático `es/zh/en` — test.
4. `t()` con cadena vacía (`by_author` en zh/en) no debe caer al español — test de i18n.
5. `sub` genérico: nunca igual al principal; con 4+ idiomas el swap usa el primer código distinto — test.
